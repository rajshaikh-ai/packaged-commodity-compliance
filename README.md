# Packaged Commodity Compliance Classification from Product Labels
**Project code: SIH26034** · *Intelligent Product Label Inspection*

**Live demo:** https://sih26034-label-inspection.streamlit.app
(free hosting: if the app has been idle it may "sleep". Click *Yes, get this app back up* and wait ~1 minute.)

A small, fully local machine-learning project. You upload a photo of a product's
packaging label. The app then:

1. cleans up the photo with OpenCV,
2. reads the text with OCR (EasyOCR),
3. extracts the label declarations (MRP, net quantity, dates, manufacturer, …),
4. feeds those features to a trained scikit-learn classifier,
5. checks the dates with explicit rules (expired? impossible dates?),
6. shows **COMPLIANT**, **NON-COMPLIANT**, or **Unable to confidently analyze label**.

> ⚠️ This is a classroom demonstration of a *configured set of label checks*.
> It is **not** a legal compliance assessment, and the model is trained on
> **synthetic** data.

---

## Features
- Drag-and-drop upload (JPG / JPEG / PNG, plus iPhone HEIC), preview, replace/reset
- OpenCV preprocessing: resize/upscale → grayscale → denoise → CLAHE contrast → adaptive threshold
- EasyOCR text extraction with words grouped back into reading lines
- Regex-based field extraction and date parsing (`31 JAN 2026`, `06/2020`, `MAY 2026`, `31/05/26`, "best before 24 months")
- Three models compared (Logistic Regression, Decision Tree, Random Forest); the best one is saved with joblib
- Hybrid decision: ML prediction + date validation
- Manual date correction for misread or handwritten dates (clearly marked **manual**)
- Expandable views: raw OCR text, every preprocessing stage, the exact feature vector sent to the model
- Model performance panel: accuracy, precision, recall, F1, confusion matrix, model comparison

## Dataset (synthetic — please read)
`dataset/product_labels.csv` is **generated by `train_model.py`**; every row has
`source = synthetic`. It is not a real regulatory dataset.

Each row describes one imaginary label using the same 9 features the app
extracts from a real photo:

| Feature | Meaning |
|---|---|
| mrp_present | MRP was detected (0/1) |
| quantity_present | Net quantity was detected |
| manufacturer_present | Manufacturer name was detected |
| address_present | Address (with PIN code) was detected |
| date_present | A manufacturing/packing or expiry date was detected |
| customer_care_present | Phone / e-mail for complaints was detected |
| expiry_detected | A use-by / expiry date was found |
| is_expired | That expiry date is before today |
| label_completeness | Fraction of the six declarations found (0–1) |

**How labels were assigned.** A row is *non_compliant* when the product is
expired, when MRP, net quantity or date is missing, or when fewer than 2/3 of
the six declarations are present. Then **5 % of labels are flipped at random**
to imitate human labelling mistakes, so no model can score 100 %.
To give the cleaning step real work, 12 values are blanked and 10 records are
entered twice (same `record_id`). The raw file has 510 rows. After cleaning,
488 rows remain (243 compliant / 245 non-compliant).

Duplicates are detected by `record_id`, not by identical feature values. With
only nine simple features, two different products can legitimately have the
same values.

**What this means for the metrics.** The model is learning to reproduce a
rule from noisy examples. The scores show how well it does that, **not** how
well it would judge real products.

## ML workflow (`train_model.py`)
1. **Load** the CSV (it is created first if it doesn't exist)
2. **Clean**: drop duplicates, drop rows with missing values, fix data types, recompute completeness
3. **Prepare features**: the 9 columns above → `X`; `label` → `y` (1 = non-compliant)
4. **Split**: 75 % train / 25 % test, stratified, `random_state=42`
5. **Train** Logistic Regression, Decision Tree, Random Forest
6. **Select** the model with the best 5-fold cross-validated F1 on the training set
7. **Evaluate** on the untouched test set → accuracy, precision, recall, F1, confusion matrix
8. **Save** `models/compliance_model.pkl`, `evaluation/metrics.json`, `evaluation/confusion_matrix.png`

## How the app decides
```
Photo ─► OpenCV ─► OCR ─► text cleaning ─► field + date extraction ─► 9 features
                                                                        │
                       ┌────────────────────────────────────────────────┤
                       ▼                                                ▼
          Layer 1: ML model predicts                     Layer 2: date rules
          compliant / non-compliant                      expired? mfg in future?
                       └──────────────────► final decision ◄────────────┘
```
- Too little text read (fewer than 8 words or fewer than 2 declarations) → **Unable to confidently analyze label**
- The label declares a date ("Use By", "Expiry", "Mfg. Date"…) but no complete date could be read → **Unable to confidently analyze label**. Any partial OCR fragments are shown, and the app asks for a manual correction instead of guessing.
- A date rule fails (expired, mfg date in the future, expiry before mfg) → **NON-COMPLIANT**, with the date shown
- Otherwise → the ML model's prediction

**How dates are found:**
1. Keyword first: a date right after `MFD`, `MFG DATE`, `PKD ON` → manufacturing; after `USE BY`, `BEST BEFORE`, `EXPIRY` → use-by.
2. "Best before N months" → computed from the manufacturing date.
3. Legend layouts (e.g. "Batch No., Mfd. & Use By Date ↑" with the values printed elsewhere): standalone dates are paired, earlier = manufacturing, later = use-by.
4. A month-only use-by date (`05/2026`) means "valid until the end of May 2026".

**Text columns.** OCR returns separate word boxes. They are grouped into
lines by height, and a wide horizontal gap starts a new line. Without that,
printed dates next to an address would merge with the address text.

The decision never uses the file name, path or a hard-coded product identity.
Only the OCR text is used.

## Installation (Windows)

### 1. Install Python
Python 3.10 – 3.13 from https://www.python.org/downloads/. Tick **"Add Python to PATH"** during setup.

### 2. Open PowerShell in the project folder
In File Explorer, open `packaged_commodity_compliance`, click the address bar, type `powershell` and press Enter.

### 3. Create a virtual environment and install the libraries
```powershell
python -m venv .venv
```
```powershell
.\.venv\Scripts\Activate.ps1
```
```powershell
pip install -r requirements.txt
```
If PowerShell blocks the activate script, run this once and try again:
```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```
> The install is large (about 1 GB) because EasyOCR uses PyTorch.

### 4. OCR engine
EasyOCR is installed by `pip` and needs **no separate installer**. The first
time you analyse an image it downloads its English model (~100 MB) into
`%USERPROFILE%\.EasyOCR`, so the **first run needs internet**. After that it
works offline. Do one analysis before the presentation so the model is
already downloaded.

## Train the model
```powershell
python train_model.py
```
Use `python train_model.py --regenerate` to rebuild the synthetic dataset.

## Run the app
```powershell
streamlit run app.py
```
Your browser opens at http://localhost:8501.

## Test both sample images
### In the app
1. **Havells LED lamp**: upload `samples/havells_led_lamp.jpg` → **Analyze Label** →
   expected 🟢 **COMPLIANT** (*No configured label issues were detected*).
2. **Odonil Neem** (dates changed by pen to Mfg 06/2020, Use by 05/2026): upload
   `samples/odonil_neem.jpg` → **Analyze Label**.
   - On the supplied photo, the pen-written last digits sit on top of dot-matrix
     print, and OCR only reads fragments (`06 0`, `05_`). The app therefore shows
     🟠 **Unable to confidently analyze label** and doesn't guess. MRP heading,
     192 g, Dabur India Ltd, address and toll-free number are all still read.
   - The **Correct a misread date** box opens automatically, right under the
     result. Type `06/2020` and `05/2026` and press **Validate** →
     🔴 **NON-COMPLIANT — EXPIRED PRODUCT**, *Expiry Date: May 2026*,
     *Reason: The declared expiry date has passed.* Both dates
     are tagged **MANUAL** so it is clear they are not OCR output.
   - If a clearer photo lets OCR read `06/20` and `05/26` fully, the
     legend-layout rule pairs them automatically and the result is NON-COMPLIANT
     without manual input.

Tip for the live demo: write the replacement digits large and dark, in a
separate blank area rather than on top of the printed digits. That gives OCR
a much better chance.

### From the command line
```powershell
python test_pipeline.py
```
This runs the full pipeline (OCR → features → model → date rules) on every
image in `samples/`, plus date-parsing and decision-logic unit checks.

## Troubleshooting
| Problem | Fix |
|---|---|
| "Model not found" | Run `python train_model.py` |
| Unable to confidently analyze label | Retake the photo: straight-on, in focus, no glare, label fills the frame |
| First analysis is slow | EasyOCR is loading/downloading its model. Later runs are faster (CPU only: ~15–40 s per photo) |
| Wrong date read | Use the manual correction box |
| OCR model download fails (`ConnectionResetError`) | Download [craft_mlt_25k.zip](https://github.com/JaidedAI/EasyOCR/releases/download/pre-v1.1.6/craft_mlt_25k.zip) and [english_g2.zip](https://github.com/JaidedAI/EasyOCR/releases/download/v1.3/english_g2.zip) in your browser and unzip both `.pth` files into `%USERPROFILE%\.EasyOCR\model` |
| "Unable to create virtual environment" / long-path errors | Put the project in a short path such as `C:\projects\packaged_commodity_compliance` |

## Limitations (good points to mention in the viva)
- The dataset is synthetic, so the metrics are educational only.
- OCR quality depends heavily on lighting, focus and glare. Handwriting is hard to read.
- The regex rules cover common Indian label formats, not every possible layout.
- The six checked declarations are a simplified subset chosen for this demo, not a full regulatory checklist.
